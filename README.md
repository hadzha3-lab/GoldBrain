# GoldBrain

GoldBrain — Android-приложение «вторая память» для фотографий.

## Что умеет MVP

- индексировать выбранные или разрешённые Android фотографии без копирования оригиналов;
- извлекать текст через ML Kit OCR;
- определять базовые визуальные метки;
- классифицировать фото как чек, книга, событие, контакт, парковка или обычная память;
- искать по естественным фразам, русским словоформам и синонимам;
- извлекать локальные полезные данные из OCR: суммы, телефоны, e-mail, ссылки, даты и ISBN;
- фотографировать через CameraX;
- индексировать галерею партиями через WorkManager;
- откладывать повреждённые или временно недоступные фото с локальным backoff, не блокируя остальную галерею;
- восстанавливать прерванную индексацию после перезапуска процесса без дублирования WorkManager-задач;
- повторно анализировать отдельную память и удалять её только из GoldBrain, не удаляя оригинал из галереи;
- запоминать локально исключённые пользователем фото, чтобы автоматическая индексация не добавляла их обратно.

## Архитектура

Код разбит по ответственности, чтобы изменения не требовали правок в одном огромном файле:

- `core/` — общие UI-компоненты и Android-разрешения;
- `data/local/` — Room база, DAO и сущности;
- `data/analysis/` — интерфейс анализа изображения и ML Kit;
- `data/gallery/` — MediaStore и индексатор галереи;
- `data/repository/` — единая точка работы с памятью;
- `domain/search/` — независимый поисковый движок;
- `background/` — WorkManager worker и расписание;
- `feature/home/` — главный экран, Route, UI state и ViewModel;
- `feature/camera/` — CameraX экран и сохранение снимков;
- `di/AppContainer.kt` — создание и переиспользование зависимостей.

`MainActivity` теперь только запускает UI и не содержит бизнес-логику.

Версии библиотек находятся в одном месте: `gradle/libs.versions.toml`.

Поиск покрыт unit-тестами в `app/src/test/`. Цепочка миграций базы дополнительно прогоняется на реальной SQLite в JVM-тестах: проверяется переход от v1 до текущей схемы и сохранность старых данных.

## Безопасность фотографий

- существующая галерея открывается только на чтение;
- приложение не запрашивает `WRITE_EXTERNAL_STORAGE`, `MANAGE_EXTERNAL_STORAGE` или другие права управления медиа;
- в коде запрещены удаление/изменение MediaStore, write-grants и writable URI;
- удаление памяти в GoldBrain удаляет только локальную запись индекса, а не оригинальный файл;
- очистка кэша ограничена собственным `cacheDir` приложения;
- CI запускает `scripts/check-media-readonly.sh` и блокирует сборку, если появится запрещённая операция;
- камера создаёт только новый снимок по явному нажатию пользователя. На Android 6–9 он хранится в app-owned storage, чтобы не выдавать приложению широкое право записи в общую галерею.


## Компактный индекс

GoldBrain не копирует оригиналы фотографий и не хранит собственные миниатюры на диске.

Для каждой памяти сохраняются только URI исходного изображения, дата, категория, короткий заголовок, несколько визуальных меток, пользовательская заметка и компактный OCR-текст. OCR ограничен 2048 символами: для длинных документов сохраняются начало и конец, чтобы не терять заголовок и итоговые суммы/реквизиты.

Дублирующий столбец `searchableText` удалён из схемы v7. Поисковый текст собирается в памяти только во время запроса.

Coil disk cache отключён, потому что изображения уже находятся в системной галерее. Room использует `TRUNCATE` journal mode, а в настройках доступны фактический размер индекса, средний размер на одну память и ручное `VACUUM` через «Сжать индекс».

Это означает, что размер индекса растёт в основном от полезного текста и метаданных, а не от размера самих фотографий.


## Большие галереи

Главный экран не загружает весь индекс в оперативную память: без поискового запроса Room отдаёт только 200 последних воспоминаний, а общее количество считается отдельным лёгким запросом.

Поисковая выдача ограничена 200 наиболее релевантными результатами. Структурированные факты из OCR (телефоны, суммы, ссылки и даты) вычисляются лениво только для запросов, которым они нужны.

Полный индекс при этом остаётся в базе и участвует в поиске.


## Потоковая индексация

GoldBrain больше не загружает весь список уже проиндексированных URI в память перед каждым пакетом.

MediaStore читается страницами по 250 записей. Для каждой страницы Room одним батч-запросом проверяет, какие URI уже есть в индексе, временно отложены после ошибки или исключены пользователем. В памяти остаётся только текущая страница и небольшой буфер кандидатов.

Порядок сканирования фиксирован как `DATE_ADDED DESC, _ID DESC`, поэтому границы WorkManager-пакетов стабильны даже когда у многих фото одинаковое время добавления.

На Android 11+ автоматическая проверка использует `MediaStore.getVersion()` и `getGeneration()`. Если при полном доступе медиатека не менялась после успешной синхронизации, шестичасовая фоновая задача не сканирует всю галерею повторно. Ручная «Индексировать сейчас» всегда остаётся принудительной.

При частичном доступе Android оптимизация пропуска не применяется: GoldBrain предпочитает лишнюю безопасную проверку риску пропустить вновь разрешённые фотографии.


## Разрешения и отмена

Перед первым широким доступом к галерее GoldBrain объясняет, что существующие фотографии используются только для чтения и локального анализа. Пользователь может отменить запрос и продолжать через системный Photo Picker для отдельных изображений.

Ручная индексация выбранных фото сериализована mutex-ом. Отмена coroutine не превращается в ошибку фотографии и не оставляет интерфейс в состоянии «индексация идёт».


## Пейджинговый поиск

При непустом запросе GoldBrain больше не загружает всю таблицу `memories` в RAM. Room читает записи по 250 штук через keyset pagination по уже существующему primary key `uri`, поэтому дополнительный SQL-индекс и дополнительное место на диске не нужны.

После каждой страницы поисковый движок оставляет только 200 лучших кандидатов. Новый ввод пользователя отменяет старый поиск между страницами. Регрессионный тест на 5 000 записей проверяет, что пейджинговое слияние даёт то же ранжирование, что и поиск по полному списку.

Проверка доступности оригиналов выполняется один раз в начале индексирующего запуска, а не на каждом 30-фото продолжении WorkManager.


## Локальные данные и Android Backup

GoldBrain хранит поисковый индекс локально и не полагается на Android Auto Backup. В manifest установлено `android:allowBackup="false"`.

Для Android 11 и ниже дополнительно задан `backup_rules.xml`, исключающий root/files/database/shared preferences/external app data. Для Android 12+ `data_extraction_rules.xml` исключает те же домены отдельно из cloud backup и device-to-device transfer.

CI проверяет эти инварианты через `scripts/check-local-data-privacy.sh`.


## Источник фотографии

GoldBrain определяет происхождение фотографии локально и не изменяет оригинальный файл. В индекс добавляются только два компактных поля: тип источника и уверенность 0–100.

Поддерживаемые типы: `CAMERA`, `DOWNLOAD`, `SCREENSHOT`, `MESSENGER`, `GOLDBRAIN`, `UNKNOWN`.

Для MediaStore используются только read-only метаданные Android: имя, относительная папка, bucket и доступный системе package owner. При массовой индексации источник определяется прямо из уже открытого Cursor, без дополнительного запроса на каждое фото.

Сильные признаки папок имеют высокий приоритет: `Download/` → скачано, `DCIM/Camera/` → камера, `Screenshots/` → скриншот, известные папки/пакеты мессенджеров → мессенджер. Снимки, созданные камерой GoldBrain, определяются с уверенностью 100%. Одно только имя вроде `IMG_1234.jpg` даёт лишь слабую уверенность.

Источник участвует в естественном поиске: «скачанные фото наушников», «мои фото машины», «скриншоты», «фото из Telegram». Если источник нельзя определить надёжно, сохраняется `UNKNOWN`, а не догадка.


## Адаптивная нагрузка

Фоновая OCR-индексация подстраивается под питание устройства. На зарядке GoldBrain обрабатывает до 30 фото за пакет и продолжает почти сразу. На обычной батарее пакет уменьшается до 15 фото с небольшой паузой. В системном энергосбережении — до 5 фото с более длинной паузой.

WorkManager дополнительно требует, чтобы батарея не была низкой. Поэтому большая первоначальная галерея индексируется быстрее на зарядке и заметно мягче по CPU/нагреву на батарее, без изменения качества OCR или поискового индекса.


## Экономный русский OCR

Медленный Tesseract-проход больше не запускается из-за нескольких случайно распознанных символов на обычной фотографии.

Дополнительный русский OCR включается для текстовых типов изображений (документы, чеки, книги, постеры, таблички, меню, визитки, скриншоты и т. п.) либо когда быстрый OCR уже нашёл достаточно большой объём текста. Если первый OCR уже вернул большой объём кириллицы, дублирующий Tesseract-проход пропускается.

Это уменьшает CPU-нагрузку и нагрев на больших галереях, не отключая русский OCR для изображений, где текст действительно важен.


## Отзыв доступа во время индексации

GoldBrain проверяет доступ к галерее перед каждым WorkManager-проходом. Если Android отозвал разрешение, worker завершается успешно без retry-цикла, очищает только внутреннее состояние сканирования и не записывает фотографии как повреждённые.

Если разрешение исчезло уже во время обработки конкретного URI, `SecurityException` отделяется от обычной ошибки изображения и также останавливает проход без добавления URI в `index_failures`.

Периодическая индексация планируется только когда одновременно включена настройка автоиндексации и у приложения действительно есть доступ к галерее. Это предотвращает повторную постановку задачи сразу после отзыва разрешения при возврате приложения на экран.
